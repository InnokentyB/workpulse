# WorkPulse Movement Scenes — тестовые сценарии

Статус: план автоматических и ручных проверок к `character-game-tdpd.md`. ID `CG-US-*` и `AC-*` из TDPD; в таблицах `US-*` — сокращение для `CG-US-*`. Приоритет P0 — необходим для запуска нового игрового сценария; P1 — качество/устойчивость. Камерные проверки используют mock media/landmarks в автоматике и реальное устройство для заключительной проверки; фиксированные движения нельзя надёжно проверить только DOM-тестом.

## Ручной приёмочный прогон и критерий завершения

1. `CG-A01` Trail Manual: до начала сменить сцену туда/обратно, затем пройти шесть циклов, остановиться на каждом этапе и сверить текстовый счёт; попытка седьмого действия ничего не меняет.
2. `CG-A02` Workshop Manual: сменить сцену в новой сессии, пройти два шага, Pause/Resume, дойти до фонаря и убедиться, что итог явно непроверенный.
3. `CG-A03` Camera на устройстве: согласие → калибровка → шесть полных двусторонних подъёмов/возвратов; между циклами Pause/Resume; проверить повторную калибровку, счёт и выключение камеры при завершении. Не считать тест пройденным только по mock landmarks.
4. `CG-A04` Отказ в камере и уход во время загрузки: убедиться в понятном восстановлении и выключении индикатора камеры; новая ручная сессия начинается с 0.
5. `CG-A05` Keyboard, узкий экран и reduced motion; затем открыть Timing Lab и главную страницу WorkPulse для проверки отсутствия регрессий.

**Релизный минимум:** все P0 автоматические проверки проходят; `CG-A01`, `CG-A02`, `CG-A04`, `CG-A05` проведены вручную; `CG-A03` требуется перед заявлением, что камера в реальности подтверждает движения. Если физическую камеру проверить нельзя, честно указать это ограничение в демо/README, не подменяя доказательство моками.
