# Desk dance — TDPD slice

User request, 2026-10-06: implement the proposed short dance and integrate it. Extend the existing browser exercise catalog, ordinary activity flow and both game scenes. Success: a user follows a seated or standing routine with rhythm and sees scene progress after confirming each phrase.

Contract: six phrases, eight beats each, 80 BPM (36 seconds of movement plus user-paced transitions). Seated by default, standing optional. Screen instructions and a movement diagram; optional original synthesized rhythm created on-device after explicit Sound on. No downloaded music, accounts or new storage. No camera recognition for dance and no claim that a timer proves physical movement. Each phrase unlocks self-report only after eight beats. Repetition is allowed, with no score penalty. Pause stops rhythm/timer, preserves completed phrases and restarts the unfinished phrase. Reset/new run clears progress. Switching to dance disables camera input; both game scenes use six self-reported phrase points. In the ordinary activity flow, six completed phrases create a guided, unverified history entry using the existing history contract.

Architecture: shared dance routine data; reusable DanceSession owns phrase timer and optional Web Audio context. MovementGame owns game progress, input mode and variant; ActivitySession delegates ordinary dances to DanceSession. Lifecycle cleanup releases audio and timers on pause, completion, reset/navigation. Visibility loss pauses the unfinished phrase. Audio unavailable/denied falls back to silent visual rhythm.
